# Admin Public Request First-Gym Protected Preview Evidence Preflight

## What We're Building

Add a protected Preview evidence preflight artifact after the first-gym evidence
run coordinator. The artifact prepares the next real operator session across
hosted rehearsal evidence, customer-observed session recording, hosted
customer-session digest proof, regeneration after evidence changes, and
downstream go/no-go/operator-run/beta-review holds.

It is a control surface only. It must not record hosted proof,
customer-observed completion, hosted digest proof, first-gym go/no-go approval,
first-gym run success, limited beta review, public self-serve readiness, live
provider activation, invite delivery, notifications, billing, POS,
access-control, or member-ledger writes.

## Why This Approach

The latest chain already has a coordinator that names the continuous evidence
lanes. The practical blocker is execution readiness for the real hosted
session: operators need exact required inputs, artifact replacement guidance,
digest requirements, regeneration commands, and stop conditions before they run
the dedicated proof writers. Adding another proof claim would fabricate
progress; adding a SHA-pinned preflight makes the next real run inspectable
without pretending it happened.

## Key Decisions

- Place the artifact after
  `admin_public_request_first_gym_evidence_run_coordinator` so it can replay
  the coordinator inspector and inherit the current hosted/customer state.
- Exact-match the real evidence sequence instead of allowing free-form command
  rows.
- Include an artifact replacement policy because the proof writers use
  create-only artifact writes; regeneration requires preserving old proof and
  choosing a new path or intentionally removing a derived control artifact.
- Keep first-gym go/no-go, first-gym operator run, limited beta review, public
  self-serve, live provider, and revenue/member-system gates blocked until
  their dedicated proof tracks are inspectable.

## Scope Boundaries

- In scope: protected Preview context confirmation, real-observation input
  requirements, exact command sequence, regeneration loop, digest hold,
  artifact replacement policy, stop conditions, inspector hardening, admin card
  wiring, tests, and durable project notes.
- Out of scope: recording evidence, producing screenshots or hosted digests,
  customer-observed session completion, sending invites/notifications, enabling
  providers, billing/POS/access/member writes, or public launch decisions.

## Success Criteria

- The preflight writer pins and replays the coordinator artifact before writing.
- The inspector rejects stale parent SHA values, proof-claim flips, appended
  command rows, unsafe live-provider flags, and artifact-policy drift.
- Admin guidance surfaces the broader next batch instead of only two narrow
  slices.
- The existing dedicated proof writers remain the only path to real proof.

## Open Questions

None for implementation. Real hosted/customer observations remain external
inputs and cannot be generated by this batch.
